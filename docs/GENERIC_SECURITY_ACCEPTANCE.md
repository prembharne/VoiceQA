# General security planner acceptance

ParcelGate is an owned, server-backed application on port 4180. It has no VoiceQA fixture marker or injected business contract. Its public API guide describes ownership, roles, authoritative pricing, CSRF and idempotency rules. Separate synthetic member and manager accounts exercise legitimate server permissions. A deliberately broken ownership mode supplies a negative control.

The model selects the actions, inputs and assertions from current browser observations. The harness subsequently checks actual server events, account roles, CSRF acceptance and unique order creation; a plausible plan or green UI does not satisfy those gates. Tests cannot access arbitrary origins, sign-in APIs or the independent testing-state endpoint through model HTTP actions. Sign-in uses local encrypted profile references and the real UI.

## Evidence review before execution

Normal security drafts that pass deterministic local validation now receive a separate model review against the current user request, public credential metadata and observed application rules. Each finding selects an actual source ID; the controller supplies its original excerpt rather than relying on a model-generated quotation. The reviewer cannot rewrite assertions, dispatch actions or add permissions. A corrected draft receives a new review. Invalid citations, transport failures and incomplete review replies block plan acceptance. Appropriate essential clarifications remain possible; a false claim that a supplied ready credential profile is missing can be corrected through the same bounded draft repair.

This review is an additional model judgment, not a formal proof of correctness. Actual outcomes and independent positive/negative acceptance controls still determine whether the suite passed. Browser automation retains its direct live-tool execution and does not generate an initial plan through this security-review path.
