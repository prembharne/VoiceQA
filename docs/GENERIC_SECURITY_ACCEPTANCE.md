# General security planner acceptance

ParcelGate is an owned, server-backed application on port 4180. It has no VoiceQA fixture marker or injected business contract. Its public API guide describes ownership, roles, authoritative pricing, CSRF and idempotency rules. Separate synthetic member and manager accounts exercise legitimate server permissions. A deliberately broken ownership mode supplies a negative control.

The model selects the actions, inputs and assertions from current browser observations. The harness subsequently checks actual server events, account roles, CSRF acceptance and unique order creation; a plausible plan or green UI does not satisfy those gates. Tests cannot access arbitrary origins, sign-in APIs or the independent testing-state endpoint through model HTTP actions. Sign-in uses local encrypted profile references and the real UI.

## Low-token Qwen acceptance

The user explicitly authorized OpenRouter `qwen/qwen3.7-flash` as the only paid fallback. `scripts/test-live-run.mjs --paid-qwen-low-tokens` permits that exact model and sets an isolated host limit of 6,000 completion tokens per call, disabled additional reasoning, and three calls per host process. QA drafting allows one draft and one repair. This does not impose a dollar budget or change saved production settings; input tokens still incur provider costs. Normal planning retains its existing provider limits rather than receiving this test cap.

`--share-guide` shares the actual live guide tab through the normal page registry. The companion observes it before drafting. This avoids an additional paid discovery conversation; it is current browser evidence, not a static fixture plan. Without that flag the discovery acceptance requires an actual recorded `read_link` call to the guide.

## Issues exposed by real requests

- Visible list items were absent from reading text. API rules in the guide never reached discovery. Reading now includes visible ordinary text, including lists and tables, while excluding private/hidden/script content. The separate real-DOM probe passed, including private sentinels. Reading is still bounded and is not proof of complete document/frame coverage.
- A full security suite hit the isolated 6,000-token output limit. JSON-mode adapters now omit unused optional action/HTTP padding; strict structured-output schemas remain unchanged. Local action and scope validation still applies.
- Generated drafts attempted private token captures and malformed credential references. Specific capture errors and bounded combined action feedback expose multiple problems in the one repair pass. No private capture is converted into an authorized public capture.
- A valid Qwen plan executed but its price write omitted a required idempotency key (400), and its duplicate check expected 200 instead of the guide's 201. These are generated-test defects, not evidence of application vulnerabilities. Evidence: `.tools/live-checks/paced-live-run-50X3VK/`; 4,550 output tokens across drafting/repair, 31 recorded steps. Ownership denial, member/manager approvals and missing-CSRF denial passed. The independent acceptance gate rejected the overall result.
- Another generated plan invented `local:session`, failing before writes because that bearer source did not exist. Evidence: `.tools/live-checks/paced-live-run-MonLZ3/`. Observations now provide bounded reference names without values; planning rejects bearer sources absent from same-origin observations or explicit documentation. Default HTTP requests already send same-origin browser cookies, including HttpOnly sessions.
- The next actual Qwen repair executed 30 recorded steps, with seven of eight HTTP checks passing, using 4,124 output tokens across drafting/repair. Own/foreign order checks, missing-CSRF denial, manager approval, duplicate response ID equality and changed-payload conflict passed. The separate pricing write still omitted its required idempotency key, and an API-only approval incorrectly expected UI text to update without a refresh. The suite also lacked a member-role denial with valid CSRF; a missing-CSRF 403 cannot prove role enforcement. Evidence: `.tools/live-checks/paced-live-run-V9M5JG/`. The full gate rejected this result as well. Expected-value/prerequisite grounding and complete requested coverage remain acceptance blockers, beyond syntactic validation.

These results do not yet establish a passing general security matrix. Correct expected outcomes, positive controls, negative ownership detection and further application categories require actual execution evidence. The broader agent goal remains active.
